> 版本：**V2.0 后台上线**
> 本文档记录线上环境的实际形态与运维方式，口令一律不写入仓库。

## 一、部署信息

| 项目 | 值 |
|---|---|
| 服务器 | 111.228.23.195，Ubuntu 22.04.3 LTS (x86_64) |
| 运行环境 | OpenJDK 17.0.21 + MySQL 8.0.46 |
| 站点目录 | `/ZJZS` |
| 访问地址 | **http://111.228.23.195:3001/** |
| 服务名 | `zjzs-rbac`（systemd，已设为开机自启） |

## 四、日常运维

```bash
systemctl status zjzs-rbac      # 状态
systemctl restart zjzs-rbac     # 重启
systemctl stop zjzs-rbac        # 停止
tail -f /var/log/zjzs-rbac.log  # 实时日志（含 Spring 与接口异常）
journalctl -u zjzs-rbac -n 100  # systemd 视角日志
```

健康检查：

```bash
curl -s http://127.0.0.1:3001/api/health
# {"code":200,"msg":"操作成功","data":{"status":"UP","app":"rbac-skeleton"}}
```

## 六、更新流程

### 6.1 只改前端

```bash
# 本地：构建并打包
cd rbac-skeleton/frontend && npx vite build
tar.exe -czf ../../.deploy-tool/static.tar.gz -C dist .

# 上传后在服务器执行
rm -rf /ZJZS/static/* && tar -xzf /tmp/static.tar.gz -C /ZJZS/static
```

前端是纯静态文件，**不需要重启服务**。`index.html` 不设长缓存、assets 带 hash，刷新即可生效。

### 6.2 改了后端

```bash
# 本地打包（需 JDK 17 + Maven）
mvn -B -DskipTests -f rbac-skeleton/backend/pom.xml clean package

# 服务器（必须先停，否则 jar 被占用替换失败）
systemctl stop zjzs-rbac
mv -f /tmp/app.jar /ZJZS/app.jar
systemctl start zjzs-rbac
```

### 6.3 改数据库结构

```bash
# 本地导出（含数据）
mysqldump -h127.0.0.1 -uroot -p --single-transaction --no-tablespaces \
  --set-gtid-purged=OFF --databases rbac_demo > database.sql
# 服务器导入
mysql < /tmp/database.sql
```

会重建库和表，线上数据会被覆盖 —— 生产环境请改成增量 SQL。

## 七、端口与外网

| 端口 | 用途 | 公网 |
|---|---|---|
| 22 | SSH | 开放 |
| 3000 | 另一个 Node 应用 | 开放 |
| **3001** | **本系统** | **开放，已实测 200** |
| 3306 | MySQL | 仅本机 127.0.0.1，未对外 |

服务器无 ufw 规则（`Status: inactive`），可达性由云厂商安全组控制。

## 八、旧站迁移说明

清空 `/ZJZS` 之前，原「中建装饰经营数据驾驶舱」静态站（Node + 3001）已备份：

```bash
/root/zjzs-backup/zjzs-static-20261117-214548.tar.gz   # 含 index.html + assets + server.js
```

旧服务 `zjzs-cockpit` 已 `stop` 并 `disable`，unit 文件仍保留在 `/etc/systemd/system/zjzs-cockpit.service`。恢复时建议解到独立目录并改 unit 的 `ROOT`，避免覆盖本系统。

## 九、安全清单

1. **admin 密码仍是 `123456`**，且 3001 公网可达，必须立即修改。
2. 服务器 root 口令曾在沟通中明文传递，建议 `passwd root` 更换并改用 SSH 密钥登录。
3. 3001 建议在安全组限制来源 IP，不要对 `0.0.0.0/0` 全开。
4. 数据库账号 `rbac` 只授权 `rbac_demo.*`，不要给 root 级权限。
5. JWT 密钥仍是 `application.yml` 里的默认值，正式对外前应换成随机串并通过环境变量注入。
