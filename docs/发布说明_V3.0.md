# V3.0 · 前台上线 发布说明

> 版本：**V3.0（前台上线）**
> 线上地址：后台 `http://111.228.23.195:3001/` · 前台 `http://111.228.23.195:3001/portal`
> 形态：单 jar + 单端口，内嵌 Tomcat 同时托管前端静态页与 `/api`

## 1. 本版包含

### 1.1 前台驾驶舱（V2.1 → V3.0 上线）

| 内容 | 说明 |
|---|---|
| 驾驶舱大厅 | 顶部「领导数据驾驶舱」通栏 + 下方 15 个部门缩略图，1366 / 1440 / 1920 宽度下均为 **5×3 宫格** |
| 缩略图 | 本地 SVG 柱状 / 折线剪影，无外部图片依赖 |
| 卡片说明 | 每格带部门名与一句话业务说明 |
| 登录入口 | 登录页「登录后台」进 `/`，「登录前台」进 `/portal`，同一套账号 |
| 舱内页 | KPI 指标、可见数据范围、「受限」原因提示、可进入舱列表 |

### 1.2 前台权限口径（方案 2）

- **大厅全可见**：`/api/portal/overview` 对任何登录账号都返回完整 16 张卡片
- **舱内按权限过滤**：`PortalService` 用 `DataScopeHelper.visibleDeptIds()` 算出可见部门集合，舱内数字只统计范围内部门
- **受限不阻断**：受限卡片照常展示、照常可点，进舱返回 `accessible=false` + 原因 + 当前账号可进入的舱（`peers`），不直接 403
- **接口不挂权限注解**：`/api/portal/*` 不写 `@RequiresPerm`，过滤发生在 Service 层，避免部门账号连大厅都打不开

实测：`admin` 16 张卡片全部可用（`scopeLabel=全部数据`）；`finance` 16 张中 1 张可用、15 张受限（`scopeLabel=本部门`）。

### 1.3 后台（V2.0 基线延续）

- 17 个一级菜单：0 领导驾驶舱 / 1–15 部门数据管理 / 16 系统管理
- 17 部门 · 17 角色 · 16 账号 · 75 菜单 · 121 条授权
- 侧边栏可左右拖拽调宽（宽度存 `localStorage`，双击复位）
- 系统管理六模块：用户 / 角色 / 菜单 / 部门 / 字典 / 操作日志

## 2. 数据库

本版同步 `sql/database.sql`（当前运行库完整导出，结构与数据），基线校验：

```
部门 17 · 角色 17 · 用户 16 · 菜单 75 · 授权 121 · 操作日志 0
```

恢复方式：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p < sql/database.sql
```

初始化账号 `admin / 123456`，部门账号 `finance`、`legal`、`market` … `project` 同为 `123456`。

## 5. 升级方式

```bash
# 服务器
systemctl stop zjzs-rbac
cp app.jar /ZJZS/app.jar
rsync -a --delete dist/ /ZJZS/static/
systemctl start zjzs-rbac
```

数据库本版无结构变更，可原地升级；需要重建时导入 `sql/database.sql`。
